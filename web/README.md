# Menu OTP website

The site for [Menu OTP](https://github.com/iambriansreed/menu-otp), built with
[Skrapa](https://skrapa.iambrian.com) and served from `menu-otp.iambrian.com`.
[`.github/workflows/deploy-web.yml`](../.github/workflows/deploy-web.yml) deploys it as
the last step of a release, so the version it shows is always one that was published.

This directory is the *skrapa root*: Skrapa runs every command from here, and
`tsconfig.json` carries its settings under a `skrapa` key. npm lives at the repository
root, shared with the release tooling, so install from there.

```bash
npm install          # in the repository root
npm run dev          # live reload at http://localhost:4159
npm run build        # static HTML into web/dist
.scripts/dev.mjs       # the demo app and this dev server together
```

## Project structure

```
tsconfig.json                # skrapa root: TypeScript config + "skrapa" settings
index.html                   # shared HTML shell (head + body)
index.tsx                    # home page: features, usage guide, download, build from source
copy.ts                      # shared "copy to clipboard" helper for code blocks
client.ts                    # home page browser JS
components/github-link.tsx   # GitHub icon link (used on every page)
development/index.html       # per-page shell for /development
development/index.tsx        # /development page: setup, scripts, how it works
development/client.ts        # development page browser JS
development/style.css        # development page-specific styles
assets/                      # copied as-is to dist/ (CSS, images, favicon)
version.json                 # generated: the app's version, for the download button
skrapa.d.ts                  # generated by every Skrapa command; don't edit
dist/                        # build output (gitignored)
```

Every `index.tsx` here that exports `Page()` becomes a route, so `index.tsx` is `/` and
`development/index.tsx` is `/development/`. Pages compile with `--rootDir` set to this
directory, which is why `version.json` lives here rather than being read from the
repository root's `package.json`.

The screenshots in `assets/` come from the app's snapshot mode, run from the repository
root:

```bash
app/scripts/demo.sh --snapshot web/assets --real-icons
```

`screenshot-copied.png` and `screenshot-edit.png` are crops of those.
